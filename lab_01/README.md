# Домашнее задание 01 
## Система управления медицинскими записями
## Выполнил Личковаха А.С.

Вариант 20: **Система управления медицинскими записями**.

Предметные сущности:
- Пользователь
- Пациент
- Медицинская запись

Требуемые операции API:
- создание нового пользователя;
- поиск пользователя по логину;
- поиск пользователя по маске имени и фамилии;
- регистрация пациента;
- поиск пациента по ФИО;
- создание медицинской записи;
- добавление медицинской записи к пациенту;
- получение истории записей пациента;
- получение записи по коду.

В рамках домашнего задания необходимо описать архитектуру в Structurizr DSL и подготовить:
- System Context diagram (C1);
- Container diagram (C2);
- Dynamic diagram;

---

Архитектура строится сверху вниз.

### Шаг 1. Роли

Для системы медицинских записей удобно выделить две роли:

1. **Администратор системы**
   - создает пользователей;
   - ищет пользователей по логину;
   - ищет пользователей по имени и фамилии.

2. **Медицинский сотрудник**
   - регистрирует пациента;
   - ищет пациента;
   - создает медицинскую запись;
   - добавляет запись к пациенту;
   - просматривает историю записей;
   - получает запись по коду.

Однако оба на диаграмме будут изображены как User

### Шаг 2. Группировка API по предметным областям

Все операции можно разбить на три группы.

**Пользователи**
- создание пользователя;
- поиск по логину;
- поиск по маске имени и фамилии.

**Пациенты**
- регистрация пациента;
- поиск пациента по ФИО.

**Медицинские записи**
- создание записи;
- добавление записи к пациенту;
- получение истории записей пациента;
- получение записи по коду.

Из такого разбиения напрямую получаются три доменных контейнера:
- `User Service`;
- `Patient Service`;
- `Appointment Service`.

### Шаг 3. Точка входа

Клиент не должен знать адрес каждого внутреннего сервиса. Поэтому перед сервисами размещается:

**API Gateway**
- принимает HTTP-запросы;
- маршрутизирует их в нужный сервис;
- может выполнять общую проверку авторизации и валидацию запроса.

### Шаг 4. Пользовательский интерфейс

Для взаимодействия медицинского сотрудника и администратора нужен Web UI


### Шаг 5. Хранение данных

**Database — PostgreSQL**

Она хранит:
- пользователей;
- пациентов;
- медицинские записи;
- связь медицинской записи с пациентом.

### Шаг 6. Внешние системы

Сервис уведомлений для оповещения пользователей.

Календарь куда можно автоматически добавлять отметки о записях пациента.


### Шаг 7. Архитектурно значимый сценарий

**«Создание медицинской записи для конкретного пациента» **.

- User;
